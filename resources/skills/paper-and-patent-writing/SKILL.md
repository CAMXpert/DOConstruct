# 论文与专利写作

## 先确定格式与论证

- 先找目标期刊、会议或专利主管机关当前的官方作者指南、格式要求和原始模板；核准适用稿件类型、版本和日期，保存原始链接及必要文件。按实际目标写，不捏造“通用官方模板”。目标未定时，先推进可确定的内容和论证，格式待定项记在工作文件中。
- 动笔前规划整篇：中心问题、已有依据、方法或技术方案、结果、结论及各章如何承接。论文让每项结论对应结果；专利让技术问题、方案、实施方式、权利要求及附图中的技术要素相互对应。沿目标要求安排结构，不预设所有文章共用的章节模板。
- 先完成章节清单与论证提纲，再逐段、逐点写 md 或 txt；最后用代码按清单组稿。修改整篇时先核对脉络，避免各段局部通顺却互相矛盾。

## 依据与表达

- 客观、真实：不编造数据、实验、文献、引文或结论。多查研究原文、原始数据、官方技术资料及实际记录；摘要、搜索片段和二手综述只作线索。重要数字、引用及关键结论回到原始出处核对。
- 区分已观察的研究事实、文献结论和作者推断。推断说明依据与适用条件；没有把握的内容不写死，缺依据时先少写、查证或在工作记录中留待补足，不用猜测填满正文。
- 不作防御性写作。需要时用准确、简短的保守措辞，例如“在本实验条件下”或“结果提示”；否则少提。不要为展示严谨加入“不能保证什么”之类与当前论证无关的免责声明。
- 图和表同样遵守真实性：数值、单位、样本与统计口径可追溯，区分实测、计算和示意；图注、表说明与正文一致。没有真实数据就不制造实验图或结果表。

## 按章节保存资产并组稿

所有分段文字、图片和表格按大段落或章节归入该文章的 assets；只建实际需要的目录。一个可用布局：

```text
article/
  sections.json
  manuscript.md                 # 或 manuscript.txt，最终组稿
  assets/
    00-plan/
      outline.md                # 全篇行文与论证规划，不拼入正文
      target-format.md          # 目标格式、原始来源与待定项
    01-introduction/
      body.md                   # 可拆成若干 md/txt 段落文件
      figures/
      tables/                   # 真实数据 CSV 等及表说明 md/txt
      sources.md                # 出处、页码/章节、支持的陈述和待核事项
    02-method/
      body.md
      figures/
      tables/
      sources.md
```

章节名随实际文章调整；必要来源记录与正文分开，包含原始 URL/DOI、版本或日期、具体页码/图表及对应陈述。格式文件、提纲、证据和工作备注不进入正文清单。正文引用图表时按最终稿所在的 `article/` 写相对路径，例如 `assets/02-method/figures/diagram.svg`；资产保留在所属章节中。

`sections.json` 显式列出章节顺序及要拼入的正文/表说明文件，文件路径相对于该章节目录；不盲目 glob 所有文件：

```json
{
  "sections": [
    {"directory": "01-introduction", "body": ["body.md"]},
    {"directory": "02-method", "body": ["body.md", "tables/table-1.md"]}
  ]
}
```

需要确定性组稿时运行本技能的 [scripts/assemble.py](scripts/assemble.py)：

```text
python scripts/assemble.py --root /path/to/article --output manuscript.md
```

脚本只拼接显式列出的 UTF-8 md/txt，不生成内容、改写引用或扫描图表/来源目录。组稿后核对章节承接、图表引用、数字与出处，以及目标当前格式要求；最终格式转换沿该目标的实际模板完成。
